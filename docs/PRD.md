# AgentWeave 产品需求

AgentWeave 是本机 Agent 资源的中央仓库。用户可以从各 Agent 收集全局资源，统一管理，再分发给选定的 Agent。中央仓库是同步时的对齐基准。

## 使用范围

- CLI 和本地网页共用一份仓库，默认在用户主目录下的 `AgentWeave` 文件夹。应用通过 npm 包安装。
- 同步范围是这台电脑上的用户级全局配置。项目级分发、任意文件夹导出和跨电脑同步在产品范围之外。
- 全局 Skills 的扫描、导入和同步覆盖 Codex、Claude Code、Pi、OpenCode、Cursor、Antigravity、Cline、Windsurf、Qwen Code、OpenClaw、Kiro、GitHub Copilot CLI 和 Kimi Code。
- MCP、全局指令和完整插件的支持情况按目标显示。完整插件可分发给 Codex、Claude Code、Pi、Cursor 和 Antigravity 桌面版。Pi 的完整插件适配范围为本地包。

## 导入和管理

- 每次打开时比较已安装 Agent 和中央仓库，首页分别提示新增、冲突和已移除的资源。点击数量可打开对应列表；只有配置残留的 Agent 不参与自动扫描。
- 本机导入先展示插件，再展示全局指令、MCP 和 Skills。独立资源与已选插件中的组件相同时默认折叠；取消整包或展开列表后可选择独立导入。冲突显示来源和原因，由用户选择版本。 两个本机插件提供同名但内容不同的 Skill 或 MCP 时，导入弹窗标明插件名和组件名，由用户选择要导入的插件。
- 本机和 GitHub 导入在预览时校验受支持的文件格式和必填字段，提示有问题的文件及原因，其他有效资源仍可选择。CLI 从 JSON 文件保存资源时也做格式校验。
- 同类型的重名资源，内容相同则合并为一份，用标签记录来源。内容不同则由用户选择要保留的版本。
- 用户可在网页或 CLI 直接新建 Skill、MCP 和全局指令。创建时写入中央仓库，Skill 根据标识、描述和 Markdown 正文生成标准的 `SKILL.md`。
- 本机导入预览可按来源 Agent 的原生格式查看和编辑单个 MCP 服务。保存只更新该服务并重新扫描；无法确认安全修改的布局或外部变化会拒绝写入。
- 本机导入预览可打开插件文件树，查看和编辑可读取的文本文件；二进制文件不可按文本编辑。冲突和重复项可分别收起，各资源分类和 Agent 分组独立展开；已勾选项始终可见。
- 中央仓库中的编辑和删除只改中央副本。目标 Agent 通过独立的分发操作应用改动。
- 中央仓库使用可编辑的 `codex/` 目录，主指令为 `AGENTS.md`，另存的指令在 `instructions/`。Skills 在 `skills/`，原始插件文件在 `plugins/`，MCP 在 `config.toml`。Codex 无法表达的连接保存在 `mcp/`。初次读取旧 SQLite 仓库时迁移并保留原数据库。分发时使用目标的全局文件名和目录。Codex 优先使用首个有内容的指令文件，按 `AGENTS.override.md`、`AGENTS.md` 查找。整类删除会预览两处已有文件，确认后清理，避免回退文件继续生效。

## MCP

- 中央配置以 MCP `2026-07-28` 规范的两种标准连接方式为基准，分别使用启动命令（stdio）和远程地址（Streamable HTTP）。旧版 SSE 可以保存，并分发到支持转换的目标。
- 同步目标展示 MCP 连接方式和全局指令路径。遇到无法转换的 MCP 连接或字段时，在预览里说明。Agent 与 MCP 服务在实际连接时决定使用的协议版本。

## 分发和差异检查

- 用户可为目标选择一种或多种资源类型，也可以只分发一个资源或一个完整插件。每次打开时检查已纳入同步的目标和类别。
- 整类同步预览显示新增、覆盖和删除。目标里后来手动添加的资源，如果中央仓库没有对应项，也会出现在删除预览中。用户确认后才改动目标。
- 单项分发只处理选中的资源。多个 Agent 共用同一位置时，预览显示共享位置和可能受影响的 Agent。

## 插件

- 本机导入标记可核实的「内置」插件，默认不勾选，支持手动导入。Codex 核对安装记录及随客户端提供的市场清单，Claude Code 识别安装记录中的 `@builtin`。普通官方市场、团队安装和 Pi 运行时扩展维持原有处理。
- 内置插件原文件只供查看。整类同步保留目标平台的内置安装，单项分发也保留同名内置版本。手动导入中央仓库的副本可以按目标能力分发给其他平台。

- 以 Codex 插件设计为基准。中央仓库使用统一的资源结构，并保留原始插件文件及来源格式，解析其中的 Skills、MCP 等组件，供整包或单项分发使用。
- 分发到其他 Agent 时，AgentWeave 使用目标所需的格式。同步范围包含 Skills 或 MCP 时，目标插件已提供的相同组件只分发一份。其他可转换的组件按所选类别独立分发；无法转换的组件在预览中提示。

## GitHub 来源

- 用户可通过公开 GitHub HTTPS 地址把资源添加到中央仓库。AgentWeave 检查用户添加的地址，并在有更新时提示。
- 打开网页时自动检查来源版本。用户先查看新增、覆盖、删除及解除关联的项目，再确认更新；版本或中央内容有变化时需要重新预览。更新后的资源通过目标同步分发到 Agent。
- 应用 GitHub 更新前重新校验文件。遇到格式错误时保留中央仓库中的原版本，并报告问题。
- 多个 GitHub 来源共享同一项资源时，单个来源的新内容如果与中央版本不同，必须由用户选择。保留中央版本会取消这次更新。采用 GitHub 新版会解除其他来源对冲突资源的关联。

## npm 包接入

- 第三方项目通过 CLI 查询兼容的接口版本和功能，再把已安装的 npm 包目录与目标 Agent 交给 AgentWeave 预览。确认时只同步包内受支持的资源，并用预览标识检查变更是否过期。
- 包中声明的 Node.js MCP 启动入口需要长期可用。无运行依赖的包可由 AgentWeave 保存到中央仓库的运行目录，有依赖的包复用持久的本机安装。
- 提供能用 `npx` 运行的示例包。示例优先复用本机兼容的 CLI，允许用户明确选择下载示例验证过的固定版本。
